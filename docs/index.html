Catalog task AGENT-048

Post an agent run
without posting your keys

agent-replay turns a transcript into a single HTML file you can attach to a bug report or drop in a thread. It has a scrubber, collapsible tool calls, inline diffs and a cost gutter. The part that took the work is the redaction, and the part that makes the redaction trustworthy is that the tool refuses to write the file at all when something credential-shaped survives.

Open a demo replay Source on GitHub

The refusal is the feature

Most redaction is a filter: it removes what it recognises and hands you the result. If it missed something, you find out when someone replies to your thread. This writes nothing until the rendered file has been scanned and come back clean, and a survivor is an error with a nonzero exit code rather than a warning you scroll past.

The scan is deliberately not the filter. It is written from scratch, with none of the same patterns, and it runs on the finished HTML rather than on the transcript. A checker that shares code with the redactor cannot catch the redactor's mistakes, because a bug in a pattern is invisible to a check built on that same pattern.

That separation earns its keep. Three times while building this, the checker and the redactor disagreed, and the checker was right every time. The clearest case: a truncated private key, a BEGIN OPENSSH PRIVATE KEY header with body but no END marker. The redactor required a complete block and skipped it. A transcript that captured the first sixty lines of an id_rsa has published enough to matter, so the redactor was raised to meet the checker rather than the check being relaxed.

Three layers, because each one misses what the others catch

LayerCatchesWould miss on its own
Known formats Provider tokens by shape: Anthropic, OpenAI, OpenRouter, GitHub, GitLab, Google, AWS, Slack, Stripe, npm, PyPI, Hugging Face, JWTs, PEM blocks whole or truncated, bearer headers, inline database passwords. ADMIN_PASSWORD=hunter2, which matches no format at all.
Assignment context A value is a secret because of what it is called. Covers dotenv, JSON, YAML, CLI flags and request headers. A bare token pasted into prose with no variable name near it.
Entropy near a secret word A long random-looking string within 90 characters of a word like api_key, even when it matches no known prefix. Nothing it is asked to catch, but it is the last-resort net rather than the first line.
Layering hides its own failures, which is a verification problem. Attacking the verify script found that emptying the known-format list entirely still passed every check, because the other two layers covered for it. That redundancy is what you want at runtime and useless for testing, since a dead layer is invisible. Each layer now has a liveness probe built from a secret only that layer can catch, so a mechanism that stops working fails the build and is named.

Over-redacting is also a failure

A tool that blanks everything passes any leak test perfectly and gets uninstalled the same afternoon, at which point it protects nobody. So roughly as many test cases assert that ordinary content survives untouched.

InputResult
keepDEBUG_TOKEN_PARSER=true Untouched. An earlier version redacted this whole line, because the entropy candidate spanned the = and swallowed the variable name.
keep await refreshAuthenticationTokenSilently() Untouched. Entropy candidates now require a digit, since camelCase identifiers do not have one and real credentials essentially always do.
keep git grep "BEGIN OPENSSH PRIVATE KEY" Untouched. A PEM header alone is not key material, so the check requires base64 body following it. Without this, any transcript discussing secret detection refuses to export, which teaches people to pass --allow-leaks.
keepA 40-character git SHA Untouched, along with content hashes and package versions.
remove /mnt/c/Users/name/ Anonymised. Home paths carry a username, and WSL, macOS and native Windows shapes are all handled, not only the local one.

The cost gutter, and the easiest way to get it wrong

An agent run is almost entirely cache reads, which are billed at a fraction of the input rate. Adding input and output tokens and multiplying by the input price overstates a long session several times over.

cache-aware  $0.3180
naive        $3.0180     9.5x too high on a single synthetic turn

An earlier captured session of 856 million tokens illustrated the mistake as roughly $12,700 instead of $1,690. Those historical figures have not been recomputed under the current response-identity rules and are included only to show the scale of the error. Provider message IDs also matter: duplicate rows and cumulative streaming updates for one response must be billed once. The same message ID remains one response if its row UUID or model label changes, and the first non-empty model label sets the price if duplicate rows disagree. When no message ID is available, the transcript row is the conservative fallback identity.

The gutter separates pricing confidence. Only listed model IDs and documented aliases receive an exact rate. A known Claude family can use a labelled family estimate. An unrecognised model keeps its tokens in the total while its dollar cost is omitted, and the report marks the dollar total as incomplete.

Every dollar figure is an API-equivalent list-price estimate in USD based on the dated source shown in the report. It is not an invoice and does not represent what a subscription user paid.

Using it

pip install -e .
agent-replay --list                          # recent transcripts
agent-replay                                 # export the most recent one
agent-replay run.jsonl -o replay.html
agent-replay run.jsonl --audit-only          # report what would be removed, write nothing
agent-replay run.jsonl --include-thinking    # reasoning blocks, excluded by default

Exit 0 on success, 1 when something survived redaction and the file was therefore not written, 2 on bad usage or an unreadable transcript.

Thinking blocks are excluded unless you ask for them. They are the model's working notes rather than its answer, and someone sharing a run to report a bug has not necessarily chosen to publish them.

An empty result is an error, not an empty file. A transcript that produces no events exits 2, because a zero-event replay looks like a clean run.

What it does not do

  • Only Claude Code transcripts. The JSONL shape is specific. Other agent formats would need their own parser.
  • A purely alphabetic secret can slip past the entropy layer, which requires a digit so that camelCase identifiers are not redacted. The known-format and assignment layers still cover the realistic cases, which is what the layering is for.
  • Encryption, reversal and chunking are not attempted. A secret split across two strings and reassembled at runtime will not be found. One layer of base64 is decoded and checked; more than one is not.
  • Cost is an API-equivalent USD estimate, not an invoice. Subscription plans, discounts, batch pricing and calls with no known rate are not included in the dollar total. Unknown-model tokens remain counted and the report marks the total as incomplete.
  • Read the file before you post it. This makes a leak much less likely and cannot make it impossible, and no tool that pattern-matches text can.
